# Хакатон-задача: умный подбор подрядчиков

Сервис для организаторов мероприятий в Казахстане. Пользователь уже получил каталог своего города; ему нужно выбрать **до трёх подходящих подрядчиков** и понять, почему именно они подходят. Проект решает задачу **#79-lite**: ценность в конкретных объяснениях, честной доступности и понятном отсутствии результатов.

## Состояние этой версии

**Это версия интерфейса участника 3, ещё не готовый сервис рекомендаций.**

- Добавлены форма Streamlit, показ карточек и трёх исходов, отметки происхождения данных, причины исключений и UI-тесты.
- В репозитории есть CSV организатора: 66 профилей, в том числе 13 синтетических.
- Пока отсутствуют `data_loader.py`, `recommender.py`, модули ранжирования, общий `requirements.txt` и согласованный JSONL. Без них экран честно сообщает, что подбор не подключён.
- Реальные рекомендации, качество объяснений, порядок и скорость всего решения пока не подтверждены. Тестовые ответы используются только в тестах, не в приложении.

Состояние проверок и передача коллегам: [приёмка](docs/acceptance.md). Общая договорённость команды: [TEAM_SPEC](codex_team_plan/TEAM_SPEC.md).

## Быстрый запуск текущей версии

Нужны Git и Python **3.11**. Проверяемое окружение участника 3: Python 3.11.9, Streamlit 1.58.0, pytest 9.1.1. Для первой установки нужен доступ к PyPI; аккаунт внешнего AI-сервиса для интерфейса не нужен.

Скачайте репозиторий и перейдите в него:

```bash

cd hack-6b3754fc-oyan-ai
```

До объединения с `main` интерфейс находится в ветке `feature/ui-readme`. Она должна быть опубликована владельцем; если удалённой ветки ещё нет, эти изменения доступны только в его рабочей копии.

```bash
git switch feature/ui-readme
```

```bash

source .venv/bin/activate
python -m pip install --only-binary=:all: streamlit==1.58.0 pytest==9.1.1
```

Команда `pip install -r requirements.txt` станет основной после того, как участник 1 добавит и зафиксирует общие зависимости и команда проверит чистую установку. В текущей версии такого файла нет.

### Подключение ядра — для интегратора

Интерфейс ожидает функции `data_loader.load_contractors(path)` и `recommender.recommend(query, contractors)` из общего контракта. По умолчанию JSONL ищется рядом с `app.py` под именем `hackathon-dataset-anonymized.jsonl`. Другой путь можно передать переменной `CONTRACTORS_DATA`:

```bash
export CONTRACTORS_DATA="/absolute/path/hackathon-dataset-anonymized.jsonl"
```

В PowerShell: `$env:CONTRACTORS_DATA = 'C:\path\hackathon-dataset-anonymized.jsonl'`.

Интерфейс не конвертирует CSV самостоятельно и не подменяет отсутствующий каталог. Форматы данных и зависимости принадлежат участнику 1.

## Как устроено решение

```text
Форма → проверка запроса → обязательные фильтры
      → сравнение допустимых → максимум 3
      → объяснения на фактах → карточки и причины отсева
```

| Часть | Владелец | Ответственность |
|---|---|---|
| Данные, фильтры, единый ответ | Участник 1 | Допуск, причины исключения, вызов ранжирования, ограничение до трёх |
| Ранжирование и объяснения | Участник 2 | Устойчивый порядок всех допустимых, факты и 1–2 предложения на карточку |
| `app.py`, документация и демо | Участник 3 | Ввод, отображение исходного порядка, честные подписи, пользовательская проверка |

UI передаёт дату как `YYYY-MM-DD`, необязательные язык и длительность — как `None`, когда они не заданы. Категории берутся из всего каталога, поэтому можно проверить категорию, отсутствующую именно в выбранном городе. Сообщение и статистика отображаются из ядра; UI не пересчитывает оценки, причины или рекомендации.

## Обязательный отбор и порядок

Это согласованные требования; их реализацию в ядре предстоит проверить:

1. Найти группу по городу и категории.
2. Исключить занятых на дату, затем кандидатов с начальной ценой выше бюджета, неподходящим форматом, указанным языком или длительностью.
3. Равенство цены бюджету и длительности максимуму допустимо. `max_hours=null` означает непривязанность к присутствию: это не отказ и не «безлимитное время».
4. Сравнивать только прошедших кандидатов. Хорошее описание не может компенсировать нарушение обязательного условия.
5. Ядро выбирает первые три и передаёт их генератору объяснений. UI сохраняет состав и порядок.

**Ранжирование опубликовано отдельно, но ещё не подключено к этой ветке.** Проверен код участника 2 в `feature/ranking`, коммит `f608398`: режим `initial_price_then_id`, версия `baseline-price-v1`, формула `score = round(-float(price_from_kzt), 6)`. Порядок: оценка по убыванию → начальная цена по возрастанию → строковый ID. Это выбор по начальной цене среди допустимых, а не оценка качества или вероятность. Для воспроизводимости должны совпадать запрос, данные, версия и режим ранжирования.

**AI внутри текущей версии не подключён.** Опубликованный модуль участника 2 использует лексический поиск фрагмента description для цитаты; это не нейросетевое понимание и не фактор оценки. Написание кода с помощью Codex не является AI-функцией готового сервиса. Модель, если её добавят, не должна изменять обязательные условия; фактический режим должен быть отражён в ответе и документации.

## Объяснения и три исхода

Карточка должна содержать имя, категорию, город, цену «от» и **1–2 предложения с проверяемыми фактами**: разница между начальной ценой и лимитом, нужный язык, длительность, формат или точный факт из описания. Текст должен объяснять действительный выбор. Фраза «идеально подходит» доказательством не является.

В опубликованном модуле участника 2 объяснение строится шаблоном: начальная цена, разница с лимитом и заявленный формат; затем буквальная цитата из description с атрибуцией «В описании указано». Evidence хранит поле-источник, значение и границы цитаты в исходном тексте. Причину порядка объясняет цена, а цитата добавляет контекст профиля. Проверка на реальных финалистах ещё впереди.

Реальный пример карточки будет добавлен после вызова настоящего `recommend`. Сейчас выдавать учебную карточку за результат приложения было бы неверно.

| Статус ядра | Что видит пользователь |
|---|---|
| `success` | 1–3 карточки и сообщение о числе подходящих; если меньше трёх — почему |
| `category_not_found` | В выбранном городе нет такой категории |
| `no_matching_candidates` | Категория есть, но все исключены; показаны причины |

Ошибка загрузки, выполнения или структуры ответа показывается отдельно. После неудачного повторного запроса предыдущие карточки удаляются, чтобы их не приняли за новый ответ.

В статистике ядра каждый исключённый учитывается **один раз**, по первой причине в фиксированном порядке. Полный список причин хранится отдельно. Должно выполняться: число профилей города/категории = допущенные + исключённые. Раскрывающийся блок показывает причины конкретных исключений, в том числе для демонстрации смены даты.

## Данные и их смысл

Источник: предоставленный организатором [CSV](docs/hackathon%20dataset%20anonymized%20.csv). Для приложения команда согласовала JSONL; сейчас его нет. Окно календаря: **23.09.2026–31.12.2026**, выбор другой даты в форме ограничен.

Пересчёт CSV: 66 профилей; 13 `synthetic=true`, 8 `city_imputed=true`, 18 `price_imputed=true`.

| Поле | Отображение и ограничение |
|---|---|
| `price_from_kzt` | Начальная цена; не окончательная смета и не обещание экономии |
| `busy_dates` | Ограничения календаря датасета; отсутствие даты не подтверждает бронь |
| `max_hours=null` | Работа не привязана к часам присутствия |
| `synthetic=true` | «Синтетический профиль» |
| `synthetic=false` | «Профиль исходного каталога», без заявления о независимой проверке |
| `city_imputed` / `price_imputed` | Город / цена проставлены при подготовке данных |

Своих профилей эта ветка не добавляет. Данные не отправляются интерфейсом внешней AI-модели. Разрешение использовать набор в хакатоне не означает отдельной лицензии на его дальнейшее коммерческое распространение.

## Демо и проверка

[Сценарий защиты](docs/demo.md) и [машиночитаемый журнал](demo_queries.json) пока явно помечены как неподтверждённые: без JSONL и реального `recommend` нельзя зафиксировать честный TOP-3.

| Сценарий | Что проверяется |
|---|---|
| Плотная категория осенью | Допустимых больше трёх; выбор и отличия объяснимы |
| Редкая категория | 1–2 результата, без искусственного дополнения |
| Все исключены | Понятные причины и корректные числа |
| Категории нет в городе | Отдельный исход, не ошибка загрузки |
| Запрос на две даты | Конкретный профиль исчезает из-за занятости на второй дате |
| Повтор запроса | Тот же порядок при одинаковых данных и режиме |

UI-тесты после установки зависимостей:

```bash
python -m pytest -q tests/test_ui.py
```

Все доступные тесты после интеграции:

```bash
python -m pytest -q
```

В Windows используйте `.\.venv\Scripts\python.exe` вместо `python`. UI-тесты используют явно синтетические фикстуры: они проверяют форму и отображение, но не доказывают качество ядра. На Python 3.11.9 прошли **27 UI-тестов**, в том числе из отдельной чистой копии исходников. Локальный сервер запущен, health-проверка вернула `ok`. Фактические результаты запусков и ограничения записаны в [docs/acceptance.md](docs/acceptance.md).

В интерфейсе измеряется время одного вызова подбора без загрузки каталога и запуска сервера. Ориентир задания — до 10 секунд; реальный замер на данных ещё не выполнен, универсальная скорость не заявляется.

## Если не запускается

- `No module named streamlit` — установите зависимости тем же Python, которым запускаете приложение; проверьте активацию `.venv`.
- «Сервис подбора ещё не подключён» — в текущей ветке отсутствуют модули участников 1/2 или их зависимости. Это ожидаемый блокер интеграции, не пустой каталог.
- «Не удалось загрузить каталог» — интегратору нужно проверить JSONL и путь `CONTRACTORS_DATA`; подробности доступны в терминале сервера.
- Порт 8501 занят — добавьте `--server.port 8502` к запуску и откройте `http://127.0.0.1:8502`.
- Не удалось скачать зависимости — проверьте доступ к PyPI. Работа без первой установки зависимостей не поддерживается.

## Ограничения и развитие

Это рекомендации, не бронирование, оплата или заявка. Не ищем новых подрядчиков и не расширяем город ради тройки. Описания — утверждения профилей, не доказательство качества. По бедным или одинаковым данным невозможно честно выдумать уникальные преимущества.

После рабочего MVP: актуализировать календари и начальные цены, добавить проверяемое происхождение фактов, оценить объяснения на пользовательских примерах. При росте каталога — индексировать город/категорию и доступность, кэшировать подготовку описаний по версии данных; модель добавлять только при измеримой пользе. Это направления развития, не готовые функции.

# Хакатон-задача: умный подбор подрядчиков

**Выберите до трёх подрядчиков для мероприятия в Казахстане и узнайте, почему каждый подходит вашему запросу.** Сервис работает с готовым каталогом: учитывает город, дату, формат, категорию, бюджет и необязательные язык и длительность. Занятые и неподходящие подрядчики не должны попадать в рекомендации.

Это руководство для жюри: **запуск → готовые запросы → проверка вариантов и объяснений → устройство решения**.

> **Статус версии:** интерфейс реализован и прошёл 27 UI-тестов. Ядро подбора и JSONL ещё не подключены к этой ветке. Сейчас при запуске отображается сообщение о недоступности подбора. Примеры ниже сверены с CSV организатора, но ещё не выполнены через настоящий `recommend`: они не являются отчётом об успешной работе приложения. Подтверждённые ответы будут записаны после интеграции.

## 1. Запустите приложение

Нужны Git, Python 3.11 и интернет для установки зависимостей. Наша часть проверена на macOS с Python 3.11.9, Streamlit 1.58.0 и pytest 9.1.1. API-ключи и личный аккаунт AI-сервиса для интерфейса не нужны.

```bash
git clone https://github.com/BAITC-Hacks/hack-6b3754fc-oyan-ai.git
cd hack-6b3754fc-oyan-ai
git switch feature/ui-readme
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --only-binary=:all: streamlit==1.58.0 pytest==9.1.1
python -m streamlit run app.py --server.address 127.0.0.1 --server.headless true --browser.gatherUsageStats false
```

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --only-binary=:all: streamlit==1.58.0 pytest==9.1.1
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.headless true --browser.gatherUsageStats false
```

Откройте **http://127.0.0.1:8501**. Для остановки нажмите `Ctrl+C` в терминале. Команды Windows приведены для этой платформы, но пока не проверены на Windows.

Установка во временное чистое окружение и запуск сервера на macOS выполнены; проверка `/_stcore/health` вернула `ok`. Это подтверждает запуск интерфейса, а не работу рекомендаций. Общий `requirements.txt` пока отсутствует; после его добавления и проверки основной командой станет `python -m pip install -r requirements.txt`.

## 2. Введите один из готовых запросов

После подключения ядра заполните поля формы значениями из таблицы и нажмите **«Подобрать подрядчиков»**. Во всех пяти запросах задайте **язык — русский, длительность — 6 часов**. Даты указаны в формате день.месяц.год, бюджет — в тенге.

**Числа в последнем столбце — контроль по текущему CSV и согласованным правилам допуска, не наблюдавшиеся ответы приложения.** Порядок финальной тройки пока не подтверждён. Полные запросы и контрольные ID находятся в [demo_queries.json](demo_queries.json), раздел `prepared_cases`.

| № | Город | Дата | Мероприятие | Категория | Бюджет, ₸ | Что проверить |
|---|---|---|---|---|---:|---|
| 1 | Алматы | 06.10.2026 | корпоратив | Ведущий | 1 000 000 | Условия проходят 6 из 10; сервис должен выбрать 3 и объяснить различия |
| 2 | Алматы | 08.10.2026 | корпоратив | Ведущий | 1 000 000 | Условия проходят 3; изменение относительно №1 объясняется занятостью |
| 3 | Алматы | 09.10.2026 | свадьба | Флорист | 300 000 | Подходят ровно 2; третью карточку добавлять нельзя |
| 4 | Алматы | 09.10.2026 | корпоратив | Ведущий | 100 000 | Подходящих нет: сначала исключены 4 занятых, затем 6 по бюджету |
| 5 | Астана | 09.10.2026 | корпоратив | Инструменталист | 1 000 000 | В городе нет такой категории; это отдельный исход |

### Запрос №1: есть из кого выбирать

По CSV условия проходят Буллма, Куррапика, Мицури Канроджи, Кики, Сон Гоку и Аня Форджер. **Это список допустимых, а не TOP-3 и не порядок рекомендаций.** Сервис должен показать максимум три карточки из этой группы.

Проверьте каждое объяснение: содержит ли оно конкретные факты именно этого профиля, связанные с запросом? Если скрыть имена, можно ли различить рекомендации? Общая фраза «отличный выбор» проверку не проходит. Затем повторите запрос: порядок должен сохраниться при тех же данных и режиме работы.

### Запрос №2: меняется только дата

Скопируйте условия №1 и замените дату на **8 октября**. По CSV на эту дату заняты Куррапика (`HK-88430`), Мицури Канроджи (`HK-44923`) и Кики (`HK-35215`), которые проходили условия 6 октября. Они не должны появиться в карточках №2.

Условия №2 проходят Аня Форджер (`HK-29829`), Буллма (`HK-44733`) и Сон Гоку (`HK-27222`). Порядок ещё предстоит подтвердить. В блоке **«Почему остальные не показаны»** должны быть видны исключённые профили и причина «Заняты на дату».

### Запрос №3: честные два варианта

В Алматы всего два флориста; по CSV оба подходят под этот запрос:

| Профиль | Начальная цена | Конкретный факт из описания | Что важно показать |
|---|---:|---|---|
| Тони Тони Чоппер (`HK-39372`) | от 200 000 ₸ | В описании указано цветочное оформление мероприятий и отелей | Цена проставлена при подготовке данных |
| Тихиро Огино (`HK-90001`) | от 250 000 ₸ | Композиции под цветовую палитру мероприятия, от букета невесты до оформления стола молодожёнов | Синтетический профиль |

Это сведения каталога для сверки, **не скопированные ответы приложения**. Оба поддерживают свадьбу и русский язык; 9 октября не входит в их занятые даты. Часы присутствия не применяются (`max_hours=null`), поэтому запрос на 6 часов не должен исключать этих флористов.

Ожидаемый смысл ответа: «Подходят два варианта; в этой категории в Алматы в каталоге всего два профиля». Конкретную формулировку выдаёт ядро. Не должно быть третьей выдуманной карточки или обещания окончательной стоимости.

### Запрос №4: категория есть, но никто не подходит

Здесь проверяется не ошибка, а нормальный пустой результат. В Алматы есть 10 ведущих, но по правилам первого отсева 4 исключаются из-за занятости, остальные 6 — из-за начальной цены выше бюджета.

Ожидаемый смысл: «В Алматы в каталоге 10 ведущих. На 9 октября под ваши условия никто не подходит: сначала исключены 4 занятых, среди оставшихся 6 превышают бюджет». Это контрольная формулировка, не запись реального ответа. Одного подрядчика нельзя дважды считать в итоговом числе исключённых.

### Запрос №5: категории нет в городе

В CSV нет инструменталистов в Астане. Ожидаемый смысл: «В Астане в каталоге сейчас нет подрядчиков категории “Инструменталист”». Не следует объяснять это занятостью, бюджетом или технической ошибкой.

## 3. Как понять, что результат правильный

- Показано **не более трёх** кандидатов, все соответствуют обязательным условиям.
- Объяснение — 1–2 предложения с проверяемыми фактами и содержательными различиями между карточками.
- Цена подписана **«от»**; разница с бюджетом не выдаётся за гарантированную экономию.
- Синтетические профили и проставленные при подготовке цена/город явно обозначены.
- При 1–2 карточках и при пустой выдаче есть понятная причина.
- Повтор запроса сохраняет порядок. Для пары дат причина изменения видна в календаре исключённых профилей.
- Техническая ошибка отображается отдельно от отсутствия подходящих вариантов.

Ориентир задания — до 10 секунд на ответ. Интерфейс показывает время вызова подбора отдельно от загрузки каталога и запуска сервера. **Реальные замеры полного сервиса ещё не выполнены.**

## 4. Что происходит внутри

```text
Запрос → обязательные фильтры → сравнение допустимых
       → до 3 кандидатов → объяснения на фактах → карточки
```

Сначала выбирается группа по городу и категории. Затем ядро проверяет занятость → начальную цену → формат → указанный язык → указанную длительность. Равенство цены бюджету и длительности максимуму допускается; `max_hours=null` не означает бесконечное время, а снимает условие присутствия. Хорошее описание не позволяет обойти фильтры.

Участник 2 опубликовал базовый модуль в `feature/ranking`, коммит `f608398`; он ещё не подключён к ядру этой ветки. Код использует `score = round(-float(price_from_kzt), 6)` и порядок: score по убыванию → цена по возрастанию → строковый ID. Режим — `initial_price_then_id`, версия — `baseline-price-v1`. Это порядок по начальной цене, не оценка качества и не вероятность.

Объяснения этого модуля состоят из начальной цены, разницы с лимитом, формата и буквальной цитаты из description. Для фактов сохраняются источник, поле и значение, для цитаты — её границы в исходном тексте. Лексический выбор цитаты не влияет на оценку. Если приведённые факты совпадают, модуль обозначает ограничение вместо выдумки.

**Нейросеть в текущем решении не подключена.** Codex использовался при разработке, но это не AI-функция приложения. Режим, данные и версия должны оставаться одинаковыми для проверки воспроизводимости.

| Статус | Значение |
|---|---|
| `success` | Есть 1–3 рекомендации |
| `category_not_found` | В городе нет выбранной категории |
| `no_matching_candidates` | Категория есть, но никто не прошёл условия |

UI отображает порядок, сообщения и статистику ядра без повторного отбора. В статистике каждый исключённый учитывается по первой причине; сумма допущенных и исключённых должна совпадать с размером группы города/категории.

## 5. Данные и ограничения

[CSV организатора](docs/hackathon%20dataset%20anonymized%20.csv) содержит 66 профилей: 13 синтетических, у 8 город и у 18 цена проставлены при подготовке. Списки занятых дат относятся к **23.09.2026–31.12.2026**; форма ограничена этим окном.

SHA-256 CSV для контрольных запросов:

```text
6a724b6b7dfb5973343e68ba18dadb60fc807d87e3d78f03ee86fb26cb089f7d
```

Для приложения согласован JSONL; пока он не добавлен. Контрольные примеры нужно повторно сверить с окончательным файлом и настоящим `recommend`.

Рекомендация не является бронированием или заявкой. Доступность известна только по календарю каталога, начальная цена — не окончательная смета. Описание отражает утверждения профиля, а `synthetic=false` не доказывает независимую проверку подрядчика. По одинаковым или бедным данным нельзя гарантировать содержательные различия.

Новых подрядчиков эта версия не добавляет. UI не отправляет данные внешней AI-модели. Отдельная публичная лицензия на дальнейшее распространение набора в репозитории не указана.

## 6. Тесты и воспроизводимость

В активированном окружении:

```bash
python -m pytest -q tests/test_ui.py
```

В Windows используйте `.\.venv\Scripts\python.exe` вместо `python`. Для всех тестов после объединения проекта: `python -m pytest -q`.

**Проверено:** 27 UI-тестов в рабочей и отдельной чистой копии; установка зависимостей в новом окружении; запуск локального сервера. Тесты проверяют форму, optional-поля, границы, порядок отображения, подписи, пустые состояния и ошибки. Их ответы — явно синтетические фикстуры, не реальные результаты подбора.

**Ещё не проверено:** реальная выдача, все demo-запросы через ядро, повтор после перезапуска полного приложения, скорость подбора, Windows и общий requirements.txt. Подробные доказательства — в [журнале приёмки](docs/acceptance.md); порядок защиты — в [docs/demo.md](docs/demo.md).

## 7. Если возникла проблема

| Что видно | Что сделать |
|---|---|
| `No module named streamlit` | Установить зависимости тем же Python, которым запускается приложение |
| «Сервис подбора ещё не подключён» | В текущей ветке это ожидаемый блокер интеграции; модули ядра ещё отсутствуют |
| «Не удалось загрузить каталог» | Проверить наличие JSONL; это ошибка данных, а не пустая рекомендация |
| Порт 8501 занят | Добавить к запуску `--server.port 8502`, открыть http://127.0.0.1:8502 |
| Установка не скачивает пакеты | Проверить доступ к PyPI; первоначальная установка требует сети |

### Интегратору: что подключить до передачи жюри

Нужны `data_loader.load_contractors(path)`, `recommender.recommend(query, contractors)`, JSONL, модули участника 2 и общие зависимости. Контракт — в [TEAM_SPEC](codex_team_plan/TEAM_SPEC.md). По умолчанию приложение ищет `hackathon-dataset-anonymized.jsonl` рядом с `app.py`; другой путь задаётся переменной `CONTRACTORS_DATA`. Ошибки подробно записываются в терминал сервера.

После подключения выполнить пять запросов выше, записать полный ответ, порядок ID, версию данных/режима и время в `verified_cases` файла `demo_queries.json`. Сверить с контролем CSV, заменить предварительные сведения фактическими ответами и проверить установку по общему requirements.txt. До этого нельзя объявлять руководство проверенным для полного сервиса.

## Команда, компоненты и развитие

Участник 1 — данные, обязательные фильтры, зависимости и интеграция. Участник 2 — ранжирование и фактические объяснения. Участник 3 — интерфейс, пользовательская приёмка, демо и это руководство.

Используются [Streamlit 1.58.0](https://pypi.org/project/streamlit/1.58.0/) (Apache-2.0) и [pytest 9.1.1](https://pypi.org/project/pytest/9.1.1/) (MIT). Каталог предоставлен организатором. AI-модели пока не используются.

После рабочего MVP: актуализация календарей и цен, пользовательская оценка объяснений, затем индексы города/категории и кэш описаний по версии данных при росте каталога. Модель имеет смысл добавлять при измеримой пользе; эти направления не заявлены как готовые функции.

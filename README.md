# Хакатон-задача: умный подбор подрядчиков

Помогаем организатору мероприятия в Казахстане выбрать **до трёх подрядчиков из уже имеющегося каталога**. Главная ценность решения — объяснить, почему каждый вариант подходит конкретному запросу, и честно сообщить, если подходящих вариантов мало или нет.

> **Готовность опубликованной версии:** интерфейс работает и проверен. Полный сервис ещё не собран: в этой ветке отсутствуют загрузчик, `recommend()`, JSONL и общие зависимости. Поэтому сейчас нельзя получить реальные рекомендации или воспроизвести итоговое демо. Ниже готовые части отделены от правил ещё не подключённого ядра.

## Что реализовано

- Форма: город, дата, тип мероприятия, категория, бюджет; язык и длительность необязательны.
- Значения списков берутся из загруженного каталога. Категория другого города остаётся доступной для проверки отсутствующей категории.
- Календарь ограничен **23.09.2026–31.12.2026**; бюджет и заданная длительность должны быть положительными.
- Отображение 1–3 карточек в порядке ядра: имя, категория, город, начальная цена и explanation без пересортировки.
- Различимые состояния результата, сообщение и статистика ядра, причины исключения конкретных профилей.
- Подписи «Синтетический профиль», «Город проставлен при подготовке данных», «Цена проставлена при подготовке данных».
- Отдельные сообщения об ошибке загрузки и ошибке сервиса; неудачный повторный запрос убирает старые карточки.

Без модулей ядра приложение показывает **«Сервис подбора ещё не подключён. Рекомендации пока недоступны»**. Тестовые профили не используются для подмены рабочего подбора.

### Установка и запуск

Нужны Git, Python 3.11, доступ к репозиторию и PyPI для установки. Проверено на macOS с Python **3.11.9**, **Streamlit 1.58.0**, **pytest 9.1.1**. Для этой версии интерфейса API-ключи и аккаунт AI-сервиса не нужны.

Клонирование ниже проверено с настроенным SSH-доступом GitHub. Получение репозитория по HTTPS без авторизации завершилось запросом учётных данных. Жюри необходимо заранее предоставить доступ либо архив этой ветки. Если вы получили архив, распакуйте его и начните с создания окружения из папки с `app.py`.

```bash
git clone --branch feature/ui-readme git@github.com:BAITC-Hacks/hack-6b3754fc-oyan-ai.git
cd hack-6b3754fc-oyan-ai
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --only-binary=:all: streamlit==1.58.0 pytest==9.1.1
python -m streamlit run app.py --server.address 127.0.0.1 --server.headless true --browser.gatherUsageStats false
```

Откройте **http://127.0.0.1:8501**. Остановка — `Ctrl+C`. Если порт занят, добавьте `--server.port 8503` и откройте http://127.0.0.1:8503.

Клонирование по SSH в новую папку, установка пакетов в новом окружении и запуск сервера выполнены. При повторной проверке сервера использован порт 8503. `requirements.txt` в текущей ветке отсутствует, поэтому команда установки из него не приводится как рабочая.

В Windows создание окружения и вызовы Python отличаются: используйте `py -3.11 -m venv .venv`, затем `.\.venv\Scripts\python.exe` вместо `python`, без активации. Запуск на Windows не проверен.

## Pipeline и границы ответственности

Согласованный путь запроса:

```text
Форма → город и категория → обязательные фильтры
      → ранжирование допустимых → максимум 3
      → объяснения на фактах → карточки и причины исключения
```

Интерфейс передаёт дату в ISO-формате, незаданные язык и длительность — как `None`. Он вызывает `load_contractors(path)` и `recommend(query, contractors)` согласно [контракту команды](codex_team_plan/TEAM_SPEC.md), но не реализует фильтры и ранжирование вместо ядра.

### Hard filters

Это требования к ещё не подключённому ядру, а не уже проверенная функциональность всего сервиса:

1. Найти группу по городу и категории.
2. Проверить занятость, начальную цену, формат, указанный язык и длительность — именно в этом порядке.
3. Не допускать занятого или неподходящего кандидата к ранжированию независимо от качества его описания.
4. Разрешать цену, равную бюджету, и длительность, равную максимуму.
5. При `max_hours=null` не применять ограничение присутствия; не трактовать это как бесконечное время работы.

Дата и цена должны проверяться кодом, а не оценкой языковой модели. Для итоговой статистики каждый исключённый учитывается по первой причине; все причины сохраняются отдельно. Правильность этих правил на реальном наборе пока не проверена через ядро.

## Ранжирование, AI и детерминизм

Модуль участника 2 опубликован в отдельной [ветке feature/ranking, коммит 2cf4aeb](https://github.com/BAITC-Hacks/hack-6b3754fc-oyan-ai/tree/2cf4aeb). Он изучен и протестирован отдельно; **в эту сборку интерфейса ещё не интегрирован**.

| Режим модуля | Фактический способ выбора |
|---|---|
| `baseline` — по умолчанию | `score = round(-float(price_from_kzt), 6)`: сначала меньшая начальная цена среди допустимых, без нейросетевого inference |
| `semantic` — с подготовленным кэшем | Косинусная близость векторов полного описания и строки из явно заданных типа мероприятия и категории; score округляется до 6 знаков |

Порядок обоих режимов: **score по убыванию → начальная цена по возрастанию → строковый ID**. Это не оценка качества подрядчика и не вероятность. Модуль возвращает всех допустимых; ограничение до трёх должен выполнить `recommend()`.

Режим фиксируется при импорте. Семантический кэш загружается с проверкой SHA-256; неизвестный текст или ошибочный кэш вызывают ошибку, а не скрытое переключение на другой способ выбора. Для повторяемости нужны одинаковые запрос, данные, код, режим и кэш.

Для подготовки векторов участник 2 предусмотрел модель **`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`**, ревизия `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`. При обслуживании запроса используется готовый кэш; модель заново не запускается. Семантический режим также выбирает буквальную цитату по близости к запросу. В baseline цитата выбирается по совпадению слов — это лексический метод, не нейросетевое понимание.

**В запускаемом `app.py` этой ветки AI-подбор не работает:** ядро, веса и кэш не включены в сборку. Реальный inference модели при данной проверке не запускался. Использование Codex при разработке не является AI-функцией продукта.

## Объяснимость

В опубликованном модуле объяснений используются начальная цена и разница с лимитом, формат и, когда заданы, дата, язык и длительность. Затем приводится буквальная цитата с подписью «В описании указано». Для evidence сохраняются поля-источники, значения и границы цитаты в тексте.

Цена всегда начальная. Отсутствие отметки в календаре не обещает бронирование. Дополнительный язык без запроса не выдаётся за преимущество. Если приведённые факты совпадают, модуль отмечает это вместо выдумывания различий.

Проверка качества: убрать имена из трёх реальных карточек и объяснить, чем каждая отличается и почему подходит запросу. Такая пользовательская проверка финальной тройки ещё не выполнена. Пример карточки из работающего `recommend()` пока отсутствует, поэтому учебная цитата не выдаётся за результат приложения.

## Три состояния результата

| Статус | Что означает | Как отображает UI |
|---|---|---|
| `success` | Есть 1–3 результата | Карточки, сообщение ядра и статистика; никаких дополнительных кандидатов |
| `category_not_found` | В городе нет этой категории | «В городе нет этой категории» и сообщение ядра |
| `no_matching_candidates` | Категория есть, но все исключены | «Никто не прошёл условия запроса», сообщение и причины исключения |

При 1–2 карточках причина малого количества должна приходить в `message`. UI не придумывает её. Ошибки загрузки, выполнения и некорректного ответа отображаются отдельно. Все три состояния проверены на UI-фикстурах; реальные сообщения ядра ещё не получены.

## Данные

В репозитории находится [CSV организатора](docs/hackathon%20dataset%20anonymized%20.csv): **66 профилей**, из них **13 синтетических**, **8** с проставленным городом и **18** с проставленной ценой. Исходные профили в нашей ветке не дополнены.

| Поля | Смысл |
|---|---|
| `id`, `anon_name`, `categories`, `city` | Идентификатор, вымышленное имя, категории и город |
| `price_from_kzt` | Цена «от» за мероприятие, не окончательная смета |
| `event_formats`, `languages` | Заявленные форматы и языки |
| `max_hours` | Максимум часов присутствия; пустое значение CSV соответствует непривязанной к присутствию услуге |
| `busy_dates` | Занятые даты внутри окна 23.09.2026–31.12.2026 |
| `description` | Утверждения профиля, не независимое подтверждение качества |
| `synthetic`, `city_imputed`, `price_imputed` | Происхождение профиля и проставленных полей; UI показывает подписи |

`synthetic=false` обозначается «Профиль исходного каталога», а не «проверенный подрядчик». Согласованный источник приложения — JSONL — пока отсутствует. UI по умолчанию ищет `hackathon-dataset-anonymized.jsonl` рядом с `app.py`; другой путь можно задать через `CONTRACTORS_DATA`. Самостоятельной конвертации или скрытой замены данных в UI нет.

## Скорость и ограничения MVP

Ориентир задания — до 10 секунд на ответ. Скорость полного подбора и холодный старт модели **не измерены в этой сборке**. Время выполнения тестов не считается скоростью рекомендаций.

Сервис по замыслу не бронирует, не отправляет заявки и не ищет новых подрядчиков. Календарь и цены отражают только датасет. Бедные или одинаковые описания ограничивают различимость объяснений. Главный текущий блокер — отсутствие собранного ядра и JSONL: завершённый пользовательский сценарий пока недоступен.

# Хакатон-задача: умный подбор подрядчиков

Решение задачи #79-lite: сервис подбора подрядчиков для мероприятий в Казахстане.

Пользователь уже выбрал тип мероприятия и получил каталог по своему городу. Помогаем ему выбрать максимум трёх подходящих подрядчиков из этого списка и понять: «Почему именно они подходят под мой запрос?»

## Текущий статус

В репозитории подготовлены инструкции команды, шаблоны документов, вспомогательные скрипты и [CSV-каталог подрядчиков](docs/hackathon%20dataset%20anonymized%20.csv). Приложение подбора и тесты пока не добавлены. Ниже описан планируемый сценарий, а не уже работающие функции.

## Как будет работать подбор

1. Пользователь указывает город, дату, тип мероприятия, категорию подрядчика и бюджет в тенге. Язык и длительность — необязательные условия.
2. Сервис проверяет город, категорию, занятость на дату, начальную цену и формат мероприятия, а также язык и длительность, если они указаны. Неподходящие кандидаты исключаются до сравнения.
3. Среди оставшихся выбирает до трёх кандидатов. Правило сравнения будет описано после реализации; одинаковый запрос к одному и тому же каталогу должен давать одинаковый порядок.
4. Каждая карточка показывает имя, категорию, город, начальную цену и 1–2 предложения с конкретными фактами из профиля и запроса.

Обязательные проверки отделены от сравнения кандидатов: хорошее описание не может компенсировать занятость или превышение бюджета. Объяснения должны показывать различия между кандидатами: запас бюджета, подходящий язык, длительность или конкретный опыт из описания. Общие фразы вроде «идеально подходит» не заменяют доказательства.

## Честность результата

- Если подходят один или два подрядчика, показываем только их и объясняем, почему вариантов меньше трёх.
- Различаем отсутствие категории в городе и отсутствие кандидатов, прошедших условия. Пустую выдачу объясняем словами.
- Синтетические профили явно обозначаем. Цена «от» не является гарантированной итоговой стоимостью.
- Отсутствие ограничения по часам (`max_hours=null`) не исключает автоматически флористов, декораторов и другие услуги, не привязанные к присутствию.

## Данные и границы проекта

Предоставленный организатором набор содержит 66 профилей, из них 13 синтетических. Календарь занятости охватывает 23 сентября — 31 декабря 2026 года. Часть городов и цен проставлена при подготовке данных и отмечена флагами `city_imputed` и `price_imputed`.

Работаем с существующим каталогом. Бронирование, отправка заявок и поиск новых подрядчиков не входят в решение. Доступность по датасету не является подтверждением бронирования.

## Запуск и проверка

Команды установки зависимостей, запуска приложения и тестов будут добавлены после реализации и проверки на чистой копии проекта. Сейчас запустить сервис из этого репозитория нельзя.

Для демонстрации необходимо подготовить и проверить:

- плотную категорию на осеннюю дату, где есть кандидаты для сравнения;
- редкую категорию с одним или двумя подходящими вариантами;
- запрос без результата с понятными причинами;
- одинаковый запрос на две даты, где состав меняется из-за занятости, и повтор запроса для проверки стабильности порядка.

Точные параметры демонстрационных запросов, способ построения объяснений, используемые технологии и план масштабирования будут добавлены вместе с работающим решением. Ориентир времени ответа по заданию — до 10 секунд; скорость пока не измерена.

# Демо итоговой сборки

Все команды выполняются из корня репозитория. Установка и запуск описаны в [README](../README.md). Основной режим — baseline; полный манифест входов и ответов находится в [demo_queries.json](../demo_queries.json), копия ответов — в [demo_responses.json](demo_responses.json).

## Автоматическая проверка

```sh
python run_demo.py --verify
python -m pytest -q tests/test_end_to_end.py
```

Первая команда каждый раз вызывает настоящий `load_contractors` и `recommend` и сверяет полный ответ с сохранённым. Успех завершается строкой `OK: 5 saved responses match the real core`. Тесты повторяют сценарии через Streamlit AppTest, проверяют источники цитат, неизменность каталога, перестановку входа и новый процесс. Итоговые результаты запуска — в [acceptance.md](acceptance.md).

## Пять сценариев

Во всех запросах язык — `русский`, длительность — `6` часов. Сценарии из меню UI только заполняют форму; затем нужно нажать «Подобрать подрядчиков».

| Сценарий | Город / дата / формат / категория / бюджет | Ожидаемый baseline-результат |
|---|---|---|
| `dense` | Алматы / 2026-10-06 / корпоратив / Ведущий / 1 000 000 ₸ | 6 допустимых; HK-88430 → HK-44923 → HK-29829 |
| `date_b` | Алматы / 2026-10-08 / корпоратив / Ведущий / 1 000 000 ₸ | 3 допустимых; HK-29829 → HK-27222 → HK-44733 |
| `rare` | Алматы / 2026-10-09 / свадьба / Флорист / 300 000 ₸ | 2 допустимых; HK-39372 → HK-90001; список не дополняется |
| `no_match` | Алматы / 2026-10-09 / корпоратив / Ведущий / 100 000 ₸ | `no_matching_candidates`; первичные причины: 4 занятых, 6 выше бюджета |
| `missing_category` | Астана / 2026-10-09 / корпоратив / Инструменталист / 1 000 000 ₸ | `category_not_found`; в городе нет категории |

У `dense` и `date_b` меняется только дата. HK-88430 и HK-44923 исчезают из тройки, поскольку 8 октября есть в их `busy_dates`, а 6 октября нет. Повтор любого запроса должен сохранять порядок и объяснения. В `rare` HK-90001 отмечен как синтетический; у HK-39372 цена проставлена при подготовке данных, а `max_hours=null` означает непривязанность к присутствию на площадке.

## Человеческая приёмка — ещё не выполнена

1. Выполнить `dense`, закрыть имена трёх подрядчиков и прочитать объяснения. Описать содержательное отличие каждой карточки; сверить конкретные утверждения с профилем и запросом.
2. Повторить запрос, затем выбрать `date_b`: проверить неизменность повтора и календарную причину смены выдачи.
3. Выполнить `rare`: проверить две карточки, причину неполной тройки и подписи synthetic / price_imputed.
4. Выполнить два пустых сценария: сообщения должны различаться, карточки предыдущего результата не должны оставаться на экране.
5. Проверить, что цена обозначена «от», отсутствие занятости не названо бронью, а дополнительный незапрошенный язык не объявлен преимуществом.

Автотесты проверяют происхождение фактов, но не заменяют оценку понятности человеком. Одинаковые или бедные исходные описания ограничивают различимость объяснений; придумывать преимущества нельзя.

Для замечания записать запрос, ID, точную фразу или порядок, ожидаемое изменение и поле профиля, которое его подтверждает. Владелец фильтров/статистики — участник 1, ranking/объяснений — участник 2, отображения — участник 3.

## Данные и режим

Каталог: `docs/hackathon dataset anonymized .csv`, 66 профилей; SHA-256 `6a724b6b7dfb5973343e68ba18dadb60fc807d87e3d78f03ee86fb26cb089f7d`. Календарь ограничен 23.09.2026–31.12.2026. Сохранённые ответы относятся к baseline и этому каталогу; после изменения данных или режима их нужно проверять заново.

В semantic порядок может отличаться. Для него нужен отдельно подготовленный кэш v2 и его SHA-256; инструкция — в [ranking_notes.md](ranking_notes.md). `run_demo.py --verify` сверяет именно baseline-снимки и не является проверкой semantic-ожиданий.

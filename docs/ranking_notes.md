Ветка: `feature/ranking`. Контракт: `codex_team_plan/TEAM_SPEC.md`, раздел 4,
и `codex_team_plan/PARTICIPANT_2.md`. Этап: базовый алгоритм и объяснения,
готовые к соединению с ядром; полное приложение ещё не проверено.

## Границы и вызов для интегратора

Принадлежащие участнику 2 файлы: `ranking.py`, `scoring.py`, `semantic.py`,
`explanations.py`, три `tests/test_*.py` и этот документ.
Загрузку, обязательные фильтры, contracts, UI, README и зависимости не менял.

```python
from ranking import rank_candidates, RANKING_METHOD, SCORING_VERSION
from explanations import build_cards

# eligible — результат обязательных фильтров участника 1
ordered = rank_candidates(eligible, query)
results = build_cards(ordered[:3], query)
# meta.ranking_method = RANKING_METHOD
# meta.scoring_version = SCORING_VERSION
```

`rank_candidates` возвращает всех переданных кандидатов, `build_cards` сохраняет
состав и порядок переданных финалистов. TOP-3 срез выполняется только ядром.
Ни одна функция не мутирует входные профили или query, включая вложенные списки.
Неподходящие профили модуль не фильтрует и из каталога ничего не добавляет.

Вход — нормализованные словари из общего контракта. ID: непустая строка или
целое число; после `str(id)` ID должны быть уникальны (`1` и `"1"` конфликтуют).
Цена — конечное неотрицательное число, description — строка, флаги — bool,
списки форматов/языков — списки. Query с положительным budget, выбранной category
и допустимыми остальными полями проверяет ядро. Отсутствующее description
обрабатывается как пустое. Ошибки ID/цены/типа description вызывают ValueError;
отсутствие обязательного ключа — KeyError. Их нельзя выдавать за отсутствие кандидатов.

Добавляемые поля ranking: `score`, `score_breakdown`, `evidence`.
Карточки добавляют `category`, `explanation`; исходные поля и флаги сохраняются.
Флаги synthetic/price_imputed/city_imputed обязан показывать UI; объяснение
дополнительно отмечает подготовленные цену и город. Synthetic не влияет на score.

## Формула и фактический режим

- `RANKING_METHOD = "initial_price_then_id"`.
- `SCORING_VERSION = "baseline-price-v1"`.
- `score = round(-float(price_from_kzt), 6)`.
- `score_breakdown = {"initial_price": score}`.
- Порядок: score по убыванию → исходная числовая цена по возрастанию → `str(id)`.

Это прозрачный порядок по начальной цене среди уже допустимых профилей, а не
оценка качества. Отрицательный score допустим, он не является вероятностью
или процентом. Одинаковые обязательные критерии не дают бонусов. Часы null,
дополнительные языки, synthetic и длина описания не улучшают позицию.
Нет случайности, времени, сетевых вызовов или скрытого переключения режима.

**Пока работает базовый алгоритм без нейросетевого inference.**
`semantic.py` реализует только `lexical_excerpt_v1`: точное совпадение слов
event_type/category с описанием для выбора цитаты. Оно не влияет на score
и не заменяет смысловое сравнение. Нормализация: casefold, ё → е; без стемминга,
синонимов и скрытых пожеланий. При равенстве берём более раннее предложение.

## Evidence и объяснения

Evidence — список `{source: "profile" | "query", field, value}`. Для description
также сохраняются `start`, `end` (Python-индексы символов, конец исключается)
и отсортированные `matched_terms`. Проверка:
`profile["description"][start:end] == evidence["value"]`.

Объяснение содержит две шаблонные фразы: начальная цена «от», арифметическая
разница с лимитом и заявленный формат; затем буквальная цитата с атрибуцией
«В описании указано». Разница вычисляется десятичной арифметикой. Это не
обещание итоговой сметы, качества, экономии, свободной даты или бронирования.
Причина порядка — цена, цитата даёт дополнительный контекст профиля.

Берётся полное короткое предложение до 240 символов. Точки десятичных чисел,
распространённые сокращения, инициалы и `;` сохраняются. Длинное предложение
не обрезается: отрезанная оговорка могла бы изменить смысл. Если короткого
фрагмента нет, сообщаем, что цитата не приведена и это не означает отсутствия
опыта. Выбор предложения эвристический; редкие сокращения и контекст соседних
предложений остаются предметом человеческой проверки. Точки внутри числа
или сокращения не являются дополнительными предложениями карточки.

Одинаковые объяснения не маскируем косметическими различиями: карточки
сообщают о совпадении приведённых фактов среди показанных. Уникальность,
«лучший» и «единственный самый дешёвый» не заявляются.

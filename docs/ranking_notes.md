`rank_candidates` возвращает всех переданных кандидатов, `build_cards` сохраняет
состав и порядок переданных финалистов. TOP-3 срез выполняется только ядром.

отсутствие обязательного ключа — KeyError. Их нельзя выдавать за отсутствие кандидатов.

Добавляемые поля ranking: `score`, `score_breakdown`, `evidence`.

## Формула и фактический режим

- `RANKING_METHOD = "initial_price_then_id"`.
- `SCORING_VERSION = "baseline-price-v1"`.
- `score = round(-float(price_from_kzt), 6)`.
- `score_breakdown = {"initial_price": score}`.
- Порядок: score по убыванию → исходная числовая цена по возрастанию → `str(id)`.

Это прозрачный порядок по начальной цене среди уже допустимых профилей, а не
оценка качества. Отрицательный score допустим, он не является вероятностью
или процентом. Одинаковые обязательные критерии не дают бонусов. Часы null,
дополнительные языки, synthetic и длина описания не улучшают позицию.
Нет случайности, времени, сетевых вызовов или скрытого переключения режима.

**В режиме baseline нейросетевое inference не используется.**
Для baseline `semantic.py` предоставляет `lexical_excerpt_v1`: точное совпадение слов
event_type/category с описанием для выбора цитаты. Оно не влияет на score
и не заменяет смысловое сравнение. Нормализация: casefold, ё → е; без стемминга,
синонимов и скрытых пожеланий. При равенстве берём более раннее предложение.

## Evidence и объяснения

Evidence — список `{source: "profile" | "query", field, value}`. Для description
также сохраняются `start`, `end` (Python-индексы символов, конец исключается)
и отсортированные `matched_terms`. Проверка:
`profile["description"][start:end] == evidence["value"]`.

Объяснение содержит две шаблонные фразы: начальная цена «от», арифметическая
разница с лимитом и заявленный формат; затем буквальная цитата с атрибуцией
«В описании указано». Разница вычисляется десятичной арифметикой. Это не
обещание итоговой сметы, качества, экономии, свободной даты или бронирования.
Причина порядка — цена, цитата даёт дополнительный контекст профиля.

Берётся полное короткое предложение до 320 символов. Точки десятичных чисел,
распространённые сокращения, инициалы и `;` сохраняются. Длинное предложение
не обрезается: отрезанная оговорка могла бы изменить смысл. Если короткого
фрагмента нет, сообщаем, что цитата не приведена и это не означает отсутствия
опыта. Выбор предложения эвристический; редкие сокращения и контекст соседних
предложений остаются предметом человеческой проверки. Точки внутри числа
или сокращения не являются дополнительными предложениями карточки.

Одинаковые объяснения не маскируем косметическими различиями: карточки
сообщают о совпадении приведённых фактов среди показанных. Уникальность,
«лучший» и «единственный самый дешёвый» не заявляются.

## A23: реализованный semantic-режим

`score = round(cosine(description_embedding, query_embedding), 6)`.
`score_breakdown = {"semantic_similarity": score}`. Диапазон [-1, 1],
не вероятность, не оценка качества и не доказательство опыта. Нет комбинации
с произвольно подобранными весами: при равенстве score идёт цена, затем ID.
Цена проверяется на валидность даже в semantic-режиме. Фильтры не меняются.

Текст запроса: `Тип мероприятия: {event_type}. Категория подрядчика: {category}.`.
Город, дата, бюджет, язык и часы не используются для придумывания стиля/опыта;
они остаются параметрами допуска ядра. Одинаковый смысловой запрос имеет
один вектор; дата меняет состав допустимых, а не описание желания пользователя.

`encode_with_local_model` получает уже загруженную закреплённую модель.
Каждый текст разбивается на части в пределах реального max_seq_length
токенизатора, по возможности на границе слова. Склейка частей точно равна
оригиналу. Модель кодирует части на CPU с batch_size=1, float32 и нормализацией;
нормированные векторы усредняются с весом числа содержательных токенов части
(для этой BERT-модели вычитаются 2 специальных токена), результат нормируется.
Это эвристика обработки длинного текста, не обученные веса ранжирования.
`eval`, один CPU-поток и deterministic algorithms задаются при подготовке.

`prepare_semantic_cache(candidates, queries, encode, *, model, revision, encoder)`
возвращает канонические UTF-8 JSON bytes. Тексты сортируются и дедуплицируются;
ключ — SHA-256 точного текста. Кроме описаний и запросов кодируются полные
короткие предложения. Версия подготовки: `event-category-ru-excerpts320-v1`.
Публичные функции ranking/cards по-прежнему имеют ровно два аргумента.

В semantic-режиме цитата — предложение с максимальной смысловой близостью
к тому же запросу, при равенстве — более раннее в исходнике. Это дополнительный
контекст; score кандидата вычислен по всему description, а не одной цитате.
В evidence сохраняются роль `semantic_scoring`, полное исходное описание,
query_text, similarity, model, revision и cache_sha256; для `semantic_excerpt`
также буквальный value/start/end и similarity предложения. Карточки проверяют
соответствие доказательств профилю, запросу и score. Цитата может содержать
саморекламу или ошибочное утверждение автора; она явно атрибутирована профилю.

### Как включить без новых runtime-зависимостей

При обычном запуске ничего не скачивается и не устанавливается. Нужны только
Python и заранее подготовленный JSON-кэш. Все настройки считываются один раз
при импорте ranking; изменения файла или environment не меняют живой процесс.

```sh
RANKING_MODE=semantic \
RANKING_SEMANTIC_CACHE=/absolute/path/embeddings.json \
RANKING_SEMANTIC_SHA256=<полный_SHA256_этого_файла> \
python3 <точка_входа_интегратора>
```

Пример выше требует подстановки пути/контрольной суммы; команда приложения ещё
не определена владельцем ядра. Файл читается в неизменяемый снимок один раз.
Метаданные импортировать из `ranking`, не из baseline-констант `scoring`:
`RANKING_METHOD="cached_sentence_embeddings_cosine"`,
`SCORING_VERSION="semantic-cosine-v1:<полный хэш кэша>"`.

Неверный mode, отсутствующий/повреждённый файл, несовпадение SHA, нулевой/NaN
вектор, незакреплённая revision, неизвестный текст описания/запроса — явная
`SemanticCacheError`. Автоматического перехода на цену нет. Резервный режим
выбирается оператором до нового запуска: `RANKING_MODE=baseline`.
Изменение данных требует новой подготовки и явной смены хэша; прежний кэш
можно оставить для воспроизведения старого результата.

import torch

torch.use_deterministic_algorithms(True)
model = SentenceTransformer(local_snapshot_path, device="cpu", local_files_only=True,
                            trust_remote_code=False, model_kwargs={"use_safetensors": True})
model.eval()
# contractors получает согласованный загрузчик участника 1 из утверждённого JSONL.
queries = [{"event_type": event, "category": category} for event, category in itertools.product(
    sorted({v for c in contractors for v in c["event_formats"]}),
    sorted({v for c in contractors for v in c["categories"]}))]
payload = prepare_semantic_cache(
    contractors, queries, lambda texts: encode_with_local_model(model, texts),
    model="sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2",
    revision="e8f8c211226b894fcb81acc59f3b34ba3efd5f42",
    encoder="ST6.1.0-T5.17.0-torch2.14.0-cpu-token-chunks-weighted-v1",

Path(output_cache_path).write_bytes(payload)
print(hashlib.sha256(payload).hexdigest())

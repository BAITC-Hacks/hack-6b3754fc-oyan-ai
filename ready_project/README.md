# Хакатон-задача: умный подбор подрядчиков

## 1. Описание решения

Сервис помогает организатору мероприятия в Казахстане выбрать **до трёх подрядчиков из существующего каталога**. Он проверяет город, категорию, дату, бюджет, формат, а при необходимости — язык и длительность. Пользователь получает карточки с начальной ценой и конкретными объяснениями либо сообщение, почему подходящих вариантов нет.

**Это самостоятельная рабочая сборка.** Выполняйте команды из этой папки, рядом с `app.py` и `requirements.txt`. При получении всей копии репозитория перейдите в `ready_project/`.

**Маршрут для жюри:** установка — раздел 6 → запуск — раздел 9 → пять готовых проверок — раздел 10. Программировать и редактировать файлы для этих проверок не нужно. Раздел «за 2 минуты» рассчитан на уже установленные зависимости.

Служебные документы `docs/CHALLENGE_BRIEF.md` и `docs/WORK_STATE.md` в корне остались от подготовки команды и не отражают готовую сборку. Инструкция проверки — этот README; состав сборки зафиксирован в `ready_project/BUILD_SOURCES.json`. Новые коммиты отдельных веток не попадают в неё автоматически.

## 2. Основной сценарий работы

1. Выберите готовый пример или самостоятельно заполните параметры мероприятия.
2. Нажмите **«Подобрать подрядчиков»**.
3. Система исключит неподходящих кандидатов и сравнит оставшихся.
4. На экране появятся максимум три карточки с объяснениями, число допустимых кандидатов и причины исключения остальных.

Если подходят один или два подрядчика, список не дополняется. Отсутствие категории в городе и отсутствие кандидатов, прошедших условия, показаны как разные результаты. Готовые входные данные и точные ответы приведены в разделе 10.

## 3. Архитектура

```text
Форма → валидация → город и категория → обязательные фильтры
      → ранжирование допустимых → первые 3 → объяснения → экран
```

| Компонент | Назначение |
|---|---|
| `app.py` | Форма Streamlit, готовые примеры и отображение ответа без повторной сортировки |
| `contracts.py` | Проверка структуры профилей и запросов, допустимых дат и значений |
| `data_loader.py` | Чтение и проверка CSV/JSONL; ошибки файла и записей не скрываются |
| `recommender.py` | Обязательные фильтры, статистика причин, вызов ранжирования и ограничение до трёх |
| `ranking.py`, `scoring.py` | Устойчивый порядок допустимых кандидатов |
| `explanations.py`, `semantic.py` | Подтверждающие факты и буквальные цитаты; дополнительный режим сравнения по embeddings |
| `run_demo.py` | Запуск настоящего подбора из терминала и сравнение с сохранёнными ответами |

Компактная структура рабочей части репозитория:

```text
README.md
ready_project/
├── app.py
├── contracts.py
├── data_loader.py
├── recommender.py
├── ranking.py / scoring.py
├── explanations.py / semantic.py
├── requirements.txt / requirements.lock
├── demo_queries.json
├── run_demo.py
├── BUILD_SOURCES.json
├── docs/
│   ├── hackathon dataset anonymized .csv
│   ├── demo_responses.json
│   └── ASSEMBLY.md
└── tests/
```

**Данные.** Включён официальный CSV с 66 профилями. Из них 13 синтетических, у 8 город и у 18 цена проставлены при подготовке данных. Календарь ограничен **23.09.2026–31.12.2026**. UI показывает соответствующие подписи; `synthetic=false` не называется независимой проверкой подрядчика.

**Обязательные фильтры.** После выбора города и категории проверки идут в порядке: занятость → начальная цена → формат → указанный язык → указанная длительность. Равенство цены бюджету и длительности максимуму проходит. `max_hours=null` означает непривязанность к присутствию, а не бесконечное время. Хорошее описание не позволяет обойти фильтры. В итоговой статистике каждый исключённый учтён один раз, по первой причине.

**Ранжирование и повторяемость.** По умолчанию используется `baseline`: `score = round(-float(price_from_kzt), 6)`. Сортировка: score по убыванию → начальная цена по возрастанию → строковый ID. Это выбор по начальной цене среди допустимых, не оценка качества. При одинаковых запросе, данных и режиме порядок сохраняется; это проверено повтором, перестановкой входного списка и отдельным процессом.

**Объяснения.** Карточка содержит цену и разницу с лимитом, сведения о формате, запрошенных условиях и цитату из описания. Для фактов сохраняются поля-источники; цитаты проверяются как буквальные фрагменты. Если приведённые факты совпадают, модуль сообщает об этом вместо выдумывания различий.

## 4. Используемые технологии

| Технология | Назначение |
|---|---|
| Python 3.11 | Логика загрузки, отбора, ранжирования и проверки |
| Streamlit 1.58.0 | Веб-интерфейс и автоматические проверки действий на экране |
| Pydantic 2.13.5 | Строгая валидация профилей и запросов |
| pytest 9.1.1 и стандартный unittest | Модульные и сквозные тесты |
| CSV и JSON | Исходный каталог, запросы и сохранённые ответы |

**AI в основном запуске:** нейросетевой inference не используется. В baseline выбор цитат лексический, а объяснения формируются шаблонами из фактов.

В коде сохранён дополнительный `semantic`-режим с косинусной близостью заранее подготовленных embeddings. Для подготовки коллегой использовалась `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, ревизия `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`. Веса и кэш в эту сборку не включены; режим не является частью описанного ниже запуска. На запросе код читает кэш, а не вызывает внешнюю модель. Подробнее — [документация модуля](docs/ranking_notes.md).

## 8. Параметры окружения

**Для локального запуска дополнительные переменные окружения не требуются.** Файл `.env` не нужен и автоматически приложением не загружается. Реальные секреты для запуска отсутствуют.

| Переменная | Обязательна | Назначение | Пример |
|---|---|---|---|
| `CONTRACTORS_DATA` | Нет | Другой путь к CSV/JSONL для UI; по умолчанию включённый CSV в `docs` | `docs/hackathon dataset anonymized .csv` |

Для обычных тестов их задавать не нужно: проверки без модели/кэша явно пропускаются. Режим `semantic` с отсутствующим или неверным кэшем завершится ошибкой, без скрытого переключения алгоритма.

## 10. Проверка основного сценария: за 2 минуты

### Шаг 1. Запустить

Запустите веб-интерфейс командой из раздела 9 и откройте его адрес. Для терминального варианта используйте `python run_demo.py --case dense` — он выполняет тот же настоящий `recommend()`, без тестового адаптера.

### Шаг 2. Ввести данные

В списке **«Готовый пример для проверки»** выберите **«1. Ведущие: выбор трёх из нескольких»**. Поля заполнятся автоматически. JSON ниже показывает соответствие полям формы; вставлять его в интерфейс не требуется. Бюджет — целое число в тенге, длительность — часы. Для собственного запроса язык можно оставить «Не указан», а длительность — пустой. Полный запрос:

```json
{
  "city": "Алматы",
  "date": "2026-10-06",
  "event_type": "корпоратив",
  "category": "Ведущий",
  "budget": 1000000,
  "duration": 6,
  "language": "русский"
}
```

### Шаг 3. Выполнить действие

Нажмите **«Подобрать подрядчиков»**. Выбор примера только заполняет форму: ответ вычисляется ядром при нажатии кнопки.

### Шаг 4. Сверить результат

Должно появиться сообщение **«Условия проходят 6, показываем 3.»** и карточки в порядке из следующего раздела. Повторное нажатие с теми же параметрами сохраняет порядок.

### Дополнительные готовые проверки

Для всех строк ниже язык — **русский**, длительность — **6 часов**. Все пять запросов прогнаны через ядро и Streamlit AppTest на включённом CSV.

| Пример | Город, дата, формат, категория, бюджет | Фактический результат в порядке выдачи |
|---|---|---|
| `dense` | Алматы; 06.10.2026; корпоратив; Ведущий; 1 000 000 ₸ | Куррапика → Мицури Канроджи → Аня Форджер |
| `date_b` | Алматы; 08.10.2026; корпоратив; Ведущий; 1 000 000 ₸ | Аня Форджер → Сон Гоку → Буллма |
| `rare` | Алматы; 09.10.2026; свадьба; Флорист; 300 000 ₸ | Тони Тони Чоппер → Тихиро Огино; всего 2, второй синтетический |
| `no_match` | Алматы; 09.10.2026; корпоратив; Ведущий; 100 000 ₸ | `no_matching_candidates`: сначала исключены 4 занятых, затем 6 по бюджету |
| `missing_category` | Астана; 09.10.2026; корпоратив; Инструменталист; 1 000 000 ₸ | `category_not_found`: такой категории в городе нет |

В интерфейсе этим проверкам соответствуют пункты списка:

| Команда / пример | Что выбрать в «Готовый пример для проверки» |
|---|---|
| `dense` | 1. Ведущие: выбор трёх из нескольких |
| `date_b` | 2. Те же условия, другая дата |
| `rare` | 3. Флористы: честные два варианта |

После каждого выбора нажмите **«Подобрать подрядчиков»**. В сценарии 3 проверьте подпись «Синтетический профиль» у Тихиро Огино и отметку о проставленной цене у Тони Тони Чоппера. В сценариях 4 и 5 карточек быть не должно; сообщения должны объяснять разные причины отсутствия результата.

Каждый пример также можно запустить отдельно из терминала, без открытого веб-приложения:

```

```

Команда печатает JSON: смотрите `response.status`, `response.message` и упорядоченный список `response.results`. У каждой карточки есть `anon_name`, `price_from_kzt` и `explanation`. `elapsed_seconds` может отличаться при каждом запуске.

В паре `dense` / `date_b` меняется **только дата**. Куррапика и Мицури Канроджи исчезают из тройки: 8 октября присутствует в их `busy_dates`. Причины видны в блоке «Почему остальные не показаны».

Изменение датасета или режима может изменить ответ; команда сверки тогда завершится ошибкой, а не объявит старые ожидания верными.

## 11. Ожидаемый результат

Основной запрос возвращает `status: success`:

| Порядок | Подрядчик | ID | Начальная цена |
|---|---|---|---:|
| 1 | Куррапика | `HK-88430` | от 500 000 ₸ |
| 2 | Мицури Канроджи | `HK-44923` | от 650 000 ₸ |
| 3 | Аня Форджер | `HK-29829` | от 700 000 ₸ |

Реальное объяснение первой карточки:

> Начальная цена — от 500 000 ₸, на 500 000 ₸ ниже лимита 1 000 000 ₸; в каталоге указан формат «корпоратив»; по календарю нет отметки о занятости на 2026-10-06; запрошенный язык «русский» указан в профиле; заявленные 6 ч покрывают запрошенные 6 ч. В описании указано: «Я, Куррапика — профессиональный ведущий мероприятий с современным подходом и тонким чувством аудитории».

В терминальном ответе поле `response.status` различает три результата:

| Статус | Что это означает | Что видно в интерфейсе |
|---|---|---|
| `success` | Подходят от одного до трёх показанных подрядчиков | Карточки, объяснения и количество прошедших условия |
| `category_not_found` | В выбранном городе нет такой категории | «В городе нет этой категории» и уточнение города и категории; карточек нет |
| `no_matching_candidates` | Категория есть, но никто не прошёл условия | «Никто не прошёл условия запроса» и число исключённых по причинам; карточек нет |

Результат также содержит `query` (отправленные условия), `results` (карточки), `stats` (счётчики), `rejections` (исключённые кандидаты), `message` (объяснение результата) и `meta` (версия алгоритма и контрольная сумма нормализованных данных). Ошибки данных и выполнения показываются отдельно и не считаются пустой выдачей.

**Цена «от» — не окончательная смета, доступность — только по данным каталога, не подтверждённая бронь.** Сервис не бронирует, не отправляет заявки и не добавляет подрядчиков ради тройки.

Три пропуска относятся к необязательным проверкам модели и семантического кэша. Проверены реальные фильтры, обе пустые выдачи, 1–3 карточки, точность цитат относительно исходного описания, повторяемость, новый процесс и все пять demo-запросов через интерфейс.

При первом сохранении пяти ответов вызов ядра занимал примерно **0,023–0,033 с** на проверяемой машине. Это разовые замеры после загрузки каталога, без запуска сервера; не гарантия скорости на другом компьютере. UI показывает время каждого вызова отдельно.

### Ограничения MVP и ручная проверка

Автоматические проверки не заменяют человеческую оценку ясности объяснений. Текущий baseline сравнивает начальную цену, не качество исполнителя; неполные или одинаковые описания ограничивают различимость карточек.

Для проверки объяснений прочитайте три карточки первого примера, мысленно скрыв имена. Должны быть понятны различия: 500 000 ₸ и 6 часов; 650 000 ₸ и 8 часов; 700 000 ₸ и 6 часов с другой цитатой. Цитата — утверждение из каталога, а не независимое подтверждение опыта. Тексты местами длинные, сравнительное преимущество не всегда сформулировано явно.

При программном вызове с языком в другом регистре (например, `РУССКИЙ`) фильтр допускает кандидата, но объяснение может ошибочно сообщить, что язык не указан. Готовые примеры и значения списка интерфейса используют согласованный регистр. Это известная ошибка сборки, а не причина исключать такого подрядчика.

Для расширения MVP потребуется обновлять каталог и календарь, проверять качество объяснений на большем наборе запросов и отдельно измерять работу на большом каталоге. Масштабируемость на таких объёмах в этой версии не проверена.

## 12. Возможные проблемы при запуске

| Проблема | Что проверить / исправить |
|---|---|
| Ошибка доступа при клонировании | Нужен доступ GitHub и настроенный SSH либо архив проекта от команды |
| `requirements.txt` не найден | Перейдите именно в `ready_project`, а не оставайтесь в корне репозитория |
| Установка требует Rust или завершается `Failed to build pyarrow` | Используйте полную команду установки с `-c requirements.lock`, как в разделе 6; чистая установка без ограничения версий не прошла проверку |
| `No module named streamlit` или `pydantic` | Активируйте `.venv` и установите зависимости через тот же `python` |
| Ошибка загрузки каталога | Проверьте файл `docs/hackathon dataset anonymized .csv` внутри сборки; уберите неверный `CONTRACTORS_DATA` |
| Ошибка семантического кэша | Для основного сценария уберите внешнюю настройку `RANKING_MODE=semantic`; по умолчанию работает baseline |
| Порт 8504 занят | Замените в команде запуска `--server.port 8504` на `--server.port 8505` и откройте http://127.0.0.1:8505 |
| `run_demo.py --verify` сообщает расхождение | Сверьте данные и режим с сохранёнными ответами; не заменяйте ожидания без проверки причины |

Подробные результаты проверки и замечания для команды: [отчёт проверки](docs/REVIEW.md).

# Evidence research

## Source order

1. Official case text, organizer materials, and provided datasets.
2. Primary authoritative sources: official product/API documentation, specifications, government or institutional publications, original datasets, and maintainer repositories.
3. Peer-reviewed or otherwise accountable primary research when a domain claim needs it.
4. Reputable secondary sources only when primary evidence is unavailable; label them as secondary and corroborate important claims.

For OpenAI product or API behavior, use official OpenAI documentation. For technical behavior of another product, use that product's official documentation and source repository. Search results, AI summaries, tutorials, forum posts, and marketing comparisons are discovery aids, not final evidence.

## Method

- Separate facts, inferences, and team assumptions.
- Open the supporting page; do not cite a search snippet.
- Check publication/update date and whether the fact is still current.
- Prefer claims that can be demonstrated inside the product over broad market statistics.
- Record only evidence that can change case selection, architecture, acceptance, or the pitch.
- If sources conflict, preserve the conflict and use the official case rules for the hackathon decision.
